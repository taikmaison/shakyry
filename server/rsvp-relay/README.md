# RSVP-relay

Маленький сервис без зависимостей (только `node:http` и встроенный `fetch`).
Принимает `POST /rsvp` со страницы приглашения и пересылает ответ гостя в
Telegram через Bot API. Существует отдельно от каталога, потому что каталог —
статический сайт, а токен бота нельзя класть в статику: её открывает браузер
любого гостя, и токен окажется прямо в исходном коде страницы.

## Развернуть на Render

1. Render → **New → Web Service** → выбрать репозиторий `taikmaison/shakyry`.
2. **Root Directory:** `server/rsvp-relay`
3. **Runtime:** Node
4. **Build Command:** оставить пустым (зависимостей нет)
5. **Start Command:** `npm start`
6. **Instance Type:** Free
7. Environment → добавить переменные (после деплоя, в разделе Environment):
   - `TELEGRAM_BOT_TOKEN` — токен из @BotFather. **Старый токен, который
     засветился в переписке, сначала отзовите: `@BotFather` → `/revoke` →
     выбрать бота.** Впишите сюда новый.
   - `TELEGRAM_CHAT_ID` — куда слать ответы. Напишите боту `/start` в
     личке, затем откройте в браузере
     `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите
     `"chat":{"id": ...}` — это число сюда.
   - `RELAY_KEY` — любая случайная строка, придумайте свою. Должна
     совпадать со значением `RELAY_KEY` в патче на странице приглашения
     (см. `public/invitations/*/index.html`, блок `ky-rsvp-relay`).
   - `ALLOWED_ORIGIN` — `https://shakyry-toy.onrender.com` (или ваш домен).

После сохранения переменных сервис сам передеплоится. Проверить, что жив:

```bash
curl https://<имя-вашего-сервиса>.onrender.com/health
```

Должно вернуть `{"ok":true}`.

## Ограничения бесплатного плана

Free-инстанс на Render засыпает при простое — первый запрос после паузы
может занять ~30–50 секунд. Гость этого не почувствует (ответ уходит в
фоне, страница ничего не ждёт), но само сообщение в Telegram может прийти
с такой задержкой.
