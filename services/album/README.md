# album — альбом гостей

Фото с праздника, которые загружают гости. Принимает только картинки (проверка по содержимому файла).

Где хранится (выбирается переменными окружения):
- **база** — SQLite `data/album.db`; если задан `DATABASE_URL` (Postgres от Neon) — там, таблицы `photos` и `album_hits`;
- **файлы** — `data/files/<id>/`, отдаются через `/files/albums/…`, до 15 МБ;
  если задан `BLOB_READ_WRITE_TOKEN` — в Vercel Blob (публично, `albums/<id>/photo-<суффикс>.jpg`): в базе и в API — полный адрес файла,
  лимит 4,3 МБ (у Vercel тело запроса не больше 4,5 МБ). Страница альбома (`web/public/album.js`) сама уменьшает фото
  до 2048 px по длинной стороне (JPEG), так что обычные фото с телефона укладываются; GIF и анимация отправляются как есть.
- на Vercel (`VERCEL=1`) без `BLOB_READ_WRITE_TOKEN` загрузка отвечает 503 (диск контейнера не постоянный — фото бы пропали),
  в логе — строка `[album] VERCEL=1, но BLOB_READ_WRITE_TOKEN не задан…`; просмотр и удаление работают.
- удаление фото и событие `invitation.deleted` удаляют и файлы (с диска или из Blob) до ответа.

Защита загрузки — до чтения тела запроса (лимиты в базе, поэтому работают и на Vercel, где экземпляры засыпают):
- с одного IP — не больше 30 попыток за 10 минут, дальше 429. IP — первый адрес `X-Forwarded-For` (его ставит шлюз или Vercel),
  без него — адрес сокета. Каждая попытка — строка в `album_hits`; строки старше часа удаляются по ходу загрузок (не чаще раза в 10 минут);
- в одном альбоме — не больше 300 фото, дальше 409 «В альбоме уже 300 фото…» (проверяется и до чтения тела, и при записи);
- имя гостя — без NUL, управляющих символов и смены направления текста, до 80 символов.

Зависит от API приглашений. Слушает событие `invitation.deleted` (удаляет фото).

## API
| Метод | Путь | Что делает |
|---|---|---|
| GET / POST | `/api/i/:id/album` | фото / загрузить (multipart: `file`, `name`) — только в опубликованное |
| DELETE | `/api/i/:id/album/:photo` | удалить фото — владелец или админ (права проверяет invitations по Cookie/Authorization); `:photo` — только цифры, иначе 404 |
| GET | `/files/albums/:id/:file` | файл фото (при хранении на диске) |
| GET | `/api/album/stats?ids=a,b` | счётчики фото `{ id: { photos } }` — только по приглашениям вошедшего (список берётся из `GET /api/invitations` сервиса приглашений с его Cookie/Authorization); чужие и неизвестные id не попадают в ответ, без `ids` — все свои, без входа 401 |
| POST | `/events` | события (шлюз снаружи не пускает) |

## Окружение
`PORT`, `HOST`, `DATA_DIR`, `INVITATIONS_API`; необязательные: `DATABASE_URL` (Postgres вместо SQLite), `BLOB_READ_WRITE_TOKEN` (фото в Vercel Blob вместо диска),
`UPLOADS_PER_IP` (по умолчанию 30 за 10 минут), `MAX_PHOTOS` (по умолчанию 300 в одном альбоме).
