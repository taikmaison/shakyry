# catalog — каталог шаблонов

Шаблоны приглашений, сборка приглашения из шаблона, музыка, медиафайлы, шрифты, превью.
Ни от каких сервисов не зависит. Данные — `content/` (только чтение).

## API
| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/templates` | каталог: `[{id, category, lang, popularity, preview, price, currency}]` |
| GET | `/api/templates/:id` | поля шаблона (`tokens`), пример данных (`sample`), музыка, превью, цена |
| POST | `/api/templates/:id/render` | `{fields}` → данные страницы приглашения; `{sample:true}` — с примером; `{raw:true}` — как есть |
| GET | `/api/music` | музыка шаблонов `[{url, title}]` |
| GET | `/fonts.css`, `/fonts/*`, `/media/*`, `/previews/*` | файлы |
| POST | `/_internal/reload` | перечитать `content/` (шлюз снаружи не пускает) |

## Окружение
`PORT`, `HOST`, `CONTENT_DIR` (по умолчанию `./content`), `PRICE` (цена шаблона, по умолчанию 3500), `CURRENCY` (по умолчанию `KZT`).
Своя цена для отдельных шаблонов — `content/prices.json`: `{ "296": 5000, "301": 0 }`; перечитывается вместе с шаблонами.

## Исправления шаблонов и шрифтов (`fixes/`, в git)
`content/` — архив из Google Drive, его не правим: исправления лежат в git и применяются поверх при загрузке.
- `fixes/templates.json` — правки компонентов: `{ "templates": { "175": [{ "type": "calendar-pro", "set": { "data.mainColor": "#f6e4d6" } }] } }`.
  Компонент выбирается по `id` или `type` (+ точный `text`), `set` — значения по путям (`data.x`, `size.height`, `position.y`).
  Правка, которая ни к чему не подошла, пишется в лог. После изменения — `POST /_internal/reload` или перезапуск.
- `fixes/fonts.css` — дописывается к `/fonts.css`: для шрифтов, где казахские буквы нарисованы неверно
  (например, в KZOptima «қ ң» как «к н»), те же семейства с `unicode-range` берут эти буквы из шрифта с правильными.
  Найти такие шрифты: `cd tools && node kz-glyphs.js http://127.0.0.1:8080` (нужен запущенный сайт).
  Там же правила для шрифтов, где верны только заглавные (KZPFMonumentaPro: строчная «к» как «қ») — `text-transform: uppercase`.
- `fixes/custom.json` — шаблоны по заказу: копия шаблона под конкретного клиента со своим номером
  (`{ "templates": { "150001": { "base": 150, "set": [ …правки как в templates.json… ] } } }`). В каталоге не видна,
  открывается по номеру (в форме сайта — «ID шаблона»: «Шаблон по заказу»). Картинки — только из `content/media`.

## Своя музыка (сверх песен из шаблонов)
Песни в публичный git не кладём: они идут отдельным маленьким архивом `content-extra.zip` в Google Drive
(внутри `content/music.json` — `{ "tracks": [{ "url": "/media/ab/….mp3", "title": "Исполнитель — Песня" }] }` — и сами файлы
`content/media/ab/….mp3`; имя файла — первые 16 знаков sha1, как у остальных медиа). Ссылка на архив — `CONTENT_EXTRA_URL`
(в `.env`, на Vercel — `ARG` в `Dockerfile.vercel`), скачивание: `node tools/fetch-content.js --extra`. В списке «Музыка»
свои песни идут первыми. Добавить песню: положить mp3 и строку в `music.json`, пересобрать архив, загрузить в Drive
новой версией того же файла (ссылка не меняется) и передеплоить.

## Инструменты
`node tools/update.js` — обновить шаблоны из открытого API; `node tools/clean.js` — очистка шаблонов;
`node tools/previews.js` — превью (нужен puppeteer: `cd tools && npm install`, и запущенный сайт);
`node tools/kz-glyphs.js [адрес]` — шрифты с неверными или отсутствующими казахскими буквами.
