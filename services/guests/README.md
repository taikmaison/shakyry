# guests — гости

Ответы на анкету и пожелания. База — SQLite в `data/guests.db` (VPS, локально) или Postgres по HTTPS,
если задан `DATABASE_URL` (Neon; для Vercel, где нет постоянного диска). Таблицы `answers`, `wishes`;
в общей базе Postgres индексы названы с префиксом `guests_`.
Принимает ответы только для опубликованных приглашений (проверяет через API приглашений).
Слушает событие `invitation.deleted`.

Ответ раскладывается по тексту кнопки (`src/rsvp.js`): `yes`, `plus_one` (с парой), `no`, `unknown` —
значениям кнопок в шаблонах верить нельзя. Повторный ответ с того же устройства (`guest_key`)
заменяет прежний (удаление и вставка — одной транзакцией). Сводка: `people = yes + 2 × plus_one`.

Уведомление владельцу об ответе отправляется до ответа гостю (не дольше 5 с; ошибка только пишется в лог):
на Vercel работа после ответа может оборваться. `/api/guests/stats` считает всё двумя запросами с `GROUP BY`.

## API
| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/i/:id/rsvp` | ответ гостя `{form_id, guest_key, action, action_text, fields}` → `{status}`; владельцу — уведомление |
| GET | `/api/i/:id/answers` | `{summary, answers}` — только владельцу и админу (права проверяет invitations по cookie) |
| GET | `/api/i/:id/answers.csv` | то же для Excel (UTF-8 с BOM, `;`) |
| GET / POST | `/api/i/:id/wishes` | пожелания / добавить `{name, message}` |
| GET | `/api/guests/stats?ids=a,b` | счётчики и сводка — только по своим приглашениям (cookie владельца, без входа 401) |
| POST | `/events` | события (шлюз снаружи не пускает) |

## Окружение
`PORT`, `HOST`, `DB_FILE`, `INVITATIONS_API`, `AUTH_API` (уведомления; без него не шлются),
`DATABASE_URL` (Postgres вместо SQLite; без него — файл `DB_FILE`).

Частота записи (ответы, пожелания) ограничена по IP в базе — таблица `guests_hits`, окно 10 минут:
работает и когда экземпляров несколько (Vercel).
