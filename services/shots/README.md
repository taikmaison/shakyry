# shots — картинка приглашения для превью ссылки

Когда ссылку `/i/<id>` отправляют в WhatsApp или Telegram, мессенджер показывает картинку из `og:image`.
Раньше это был снимок примера шаблона — с образцовыми именами («Айдос & Аружан»). Теперь — снимок первого экрана
самого приглашения: свой Chromium (puppeteer-core) открывает `/i/<id>?shot=1` через шлюз (`SITE_INTERNAL_URL`)
и сохраняет JPEG 780×1380 в `data/` (том `shots-data`).

- `GET /og/i/<id>.jpg?v=…` — снимок опубликованной версии. Что снимать, сервис решает сам по данным из `INVITATIONS_API`;
  `v` (его ставит веб-сервис) только меняет адрес, чтобы мессенджер не показал старую картинку после правки.
  Снимок не получился за 40 с — 302 на пример шаблона `/previews/<шаблон>.jpg`, как было раньше.
- `POST /_internal/warm/<id>` — снять заранее: веб-сервис зовёт при открытии приглашения (снаружи закрыто шлюзом).
- `POST /events` — `invitation.published` → снять заранее; `invitation.unpublished`, `invitation.deleted` → удалить снимки.
- Снимки делаются по одному; браузер закрывается через 5 минут простоя. Прежние снимки приглашения удаляются после нового.

Работает только в Docker (`docker-compose.yml`): нужен Chromium из образа. Без сервиса (локальный `node run.js`, Vercel)
веб-сервис ставит в `og:image` пример шаблона, как раньше.
