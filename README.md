# Шақыру — генератор онлайн-приглашений

Выбираешь шаблон, пишешь имена, дату, адрес, ссылку на карту — получаешь готовое приглашение:
конверт, музыка, календарь и таймер, анкета «приду / не приду», пожелания гостей, альбом фото.
Фронтенд и сервер написаны с нуля; из внешнего источника взяты только данные шаблонов
(раскладка, тексты-заготовки) и их медиафайлы.

## Как это работает для людей

1. Любой открывает сайт, выбирает шаблон, заполняет поля и смотрит **предпросмотр** — без регистрации.
2. Чтобы **сохранить черновик**, нужно войти: через Telegram или кодом на почту. Паролей нет.
3. Готовый черновик автор **отправляет на модерацию**.
4. **Админ** (он один) смотрит приглашение в `/admin` и одобряет или отклоняет с причиной.
   Автору приходит уведомление в Telegram (или на почту).
5. После одобрения ссылка `/i/<id>` открывается гостям. Если автор потом что-то поменяет,
   гости видят прежнюю одобренную версию, пока админ не одобрит новую.
6. Гости отвечают в анкете. Ответ сам раскладывается по тексту кнопки на «придёт», «придёт с парой»,
   «не придёт»; повторный ответ с того же телефона заменяет прежний. Автор видит сводку
   («придут N человек») и может скачать CSV для Excel; о каждом ответе ему приходит уведомление.

## Запуск

Нужен только [Node.js](https://nodejs.org) 22.5+ (встроенный SQLite). Зависимостей нет.

```
node run.js
```
или `start.bat`. Откройте http://127.0.0.1:8024/

Секреты — в файле `.env` (образец — `.env.example`, в git не попадает):

| Переменная | Зачем |
|---|---|
| `AUTH__TELEGRAM_BOT_TOKEN` | вход через Telegram и уведомления; токен выдаёт @BotFather |
| `AUTH__SMTP_HOST`, `AUTH__SMTP_PORT`, `AUTH__SMTP_USER`, `AUTH__SMTP_PASS`, `AUTH__SMTP_FROM` | вход кодом на почту |
| `AUTH__DEV_LOGIN_CODES=1` | только для разработки: код входа приходит прямо в ответе, без почты |
| `PUBLIC_URL` | адрес сайта для ссылок (SEO, превью в мессенджерах, уведомления) |

Приставка `AUTH__` значит «передать только сервису auth» — другие сервисы этих секретов не видят.

### Назначить админа (один раз)

Стать админом через сайт нельзя. Админ один, назначается командой на сервере:

1. Создайте бота у [@BotFather](https://t.me/BotFather), запишите токен в `.env` как `AUTH__TELEGRAM_BOT_TOKEN=...`, запустите `node run.js`.
2. Войдите на сайт через Telegram.
3. Выполните:
   ```
   cd services/auth
   node tools/make-admin.js @ваш_ник
   ```
   Роль привязывается к числовому Telegram id, так что смена ника её не сбросит.
   Передать роль другому: `node tools/make-admin.js @другой --replace`.

## Адреса

| Адрес | Что это |
|---|---|
| `/` | генератор: каталог шаблонов, форма, вход, «Мои приглашения», ответы гостей |
| `/i/<id>` | приглашение для гостей (только одобренное); `?draft` — черновик автору и админу |
| `/i/<id>/album` | альбом: гости добавляют фото с праздника |
| `/t/<id>` | пример шаблона с тестовыми данными |
| `/admin` | модерация, все приглашения, пользователи — только админу |
| `/kz/…`, `/ru/…` | посадочные страницы для поисковиков |
| `/sitemap.xml`, `/robots.txt` | для поисковиков |

## Архитектура: независимые сервисы

```
                         ┌──────────── gateway :8024 ────────────┐
                         │  единственный вход снаружи; маршруты   │
                         │  в routes.json; /_internal и /events   │
                         │  снаружи закрыты                       │
   ┌───────────┬─────────┼───────────┬───────────┬───────────────┼──────────┐
   ▼           ▼         ▼           ▼           ▼               ▼          
 auth      catalog   invitations   guests      album            web
 :8036     :8031     :8032         :8033       :8034            :8035
```

| Сервис | Отвечает за | Свои данные | Кого вызывает (по HTTP) |
|---|---|---|---|
| `auth` | вход (Telegram, почта), сессии, пользователи, уведомления | `auth.db` | — |
| `catalog` | шаблоны, сборка приглашения из шаблона, музыка, медиа, шрифты, превью | `content/` | — |
| `invitations` | черновики, модерация, одобренные версии | `invitations.db` | catalog, auth |
| `guests` | ответы на анкету, сводка, CSV, пожелания | `guests.db` | invitations, auth |
| `album` | фото гостей | `album.db` + файлы | invitations |
| `web` | страницы, SEO, фронтенд (`public/`) | — | catalog, invitations |
| `gateway` | единая точка входа | — | все |

Правила:

- **Сервисы ничего не знают друг о друге, кроме адреса API.** Адреса приходят из переменных
  окружения (`CATALOG_API`, `AUTH_API`, …). Общего кода нет: у каждого своя копия `lib/http.js`
  и `lib/db.js`, свой `package.json`, `Dockerfile` и README.
- **У каждого своя база**, чужие базы никто не читает.
- **Удаление — событием.** `invitations` шлёт `invitation.deleted` подписчикам из
  `EVENT_SUBSCRIBERS`, и `guests` с `album` сами чистят свои данные.
- **Вход проверяет только `auth`.** Остальные пересылают cookie `sid` в `GET /api/auth/me`.
- Упал один сервис — остальные работают: без `guests` приглашение открывается, просто без анкеты.

`services.json` описывает локальный запуск: порты и кто кого вызывает (по имени сервиса).
Сами сервисы этот файл не читают — `run.js` превращает его в переменные окружения.

```
node run.js                  все сервисы, упавший перезапускается
node run.js catalog web      только указанные
node run.js --offset=100     все порты +100 (второй экземпляр рядом)
```

Или по отдельности: `cd services/<имя> && npm start` (переменные — по `.env.example` сервиса).

### Docker

```
docker compose up --build
```
Каждый сервис — свой контейнер со своим томом данных; наружу открыт только шлюз (8024).
Админ: `docker compose exec auth node tools/make-admin.js @ваш_ник`.

### Публикация в интернете

Нужен VPS с Docker (2 ГБ памяти, 20 ГБ диска хватит) и домен.
Netlify и статический хостинг Render не подходят: сайту нужен постоянный диск (базы, фото гостей)
и постоянно работающий процесс для Telegram-бота. Vercel — только как временный вариант (ниже). Для домена `.kz` сервер должен
стоять в Казахстане; там же по закону РК должны храниться персональные данные пользователей.

1. A-запись домена (и `www`) → IP сервера.
2. `git clone` проекта на сервер, затем шаблоны и медиа: `CONTENT_URL=<ссылка на архив в Google Drive>` в `.env` и
   `docker run --rm -v "$PWD/services/catalog:/c" -w /c --env-file .env node:24-alpine node tools/fetch-content.js`
   (подробнее — `services/catalog/content/README.md`).
3. В `.env` на сервере: `DOMAIN=ваш-домен.kz`, `PUBLIC_URL=https://ваш-домен.kz`, `AUTH__TELEGRAM_BOT_TOKEN=...`.
4. Запуск: `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build`.
   Caddy сам получит HTTPS-сертификат; шлюз наружу не открыт.
5. Войти через Telegram и назначить админа: `docker compose exec auth node tools/make-admin.js @ваш_ник`.

Резервная копия — тома `auth-data`, `invitations-data`, `guests-data`, `album-data`.

### Vercel (временно)

Тот же код работает на Vercel Services: каждый сервис — контейнер из своего `Dockerfile`, шлюза нет —
его таблицу маршрутов заменяют `rewrites` в `vercel.json` (`/_internal/*` и `/events` наружу не открыты).
Режим выбирают переменные окружения; без них всё работает как на VPS (SQLite, диск, long-polling).

Что нужно:
1. Тариф **Pro**: сайт принимает оплату, а Hobby — только для некоммерческого использования.
2. Проект из GitHub, в настройках Build and Deployment → Framework Preset = **Services**, регион — `fra1` (задан в `vercel.json`).
3. Storage → Marketplace → **Neon Postgres**, регион **AWS Europe Central 1 (Frankfurt, `eu-central-1`)** — рядом с `fra1`,
   иначе каждый запрос к базе идёт через полмира. Появится `DATABASE_URL` (одна база на все сервисы, у каждого свои таблицы).
4. Storage → **Blob**, регион — ближайший к `fra1` (Frankfurt) — появится `BLOB_READ_WRITE_TOKEN` (фото альбомов).
   Neon и Blob подключить ко **всем** окружениям, которые деплоятся (Production и Preview): без `DATABASE_URL`
   сервис уйдёт в режим SQLite на временном диске контейнера и потеряет данные.
5. Переменные проекта (Settings → Environment Variables, видны всем сервисам — без префиксов `AUTH__`):
   `PORT=3000`, `PUBLIC_URL=https://<адрес сайта>`, `COOKIE_SECURE=1`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK=1`, `CONTACT_WHATSAPP`,
   `PAYMENT_DETAILS`, `SITE_NAME`, `DEFAULT_LANG`, `CONTENT_URL` (нужна при сборке: catalog скачивает шаблоны в образ,
   см. `services/catalog/Dockerfile.vercel`). Адреса сервисов (`CATALOG_API`, `AUTH_API`, ...) Vercel подставляет сам
   из `bindings` — в настройки их не добавлять.
   Удобно держать их в локальном `.env.vercel` (в git и на Vercel не попадает) и вставить целиком: в Environment Variables
   вставка содержимого файла в поле Key сама разбивает его на переменные.
6. Деплой — пушем в GitHub. После первого деплоя `PUBLIC_URL` должен совпасть с настоящим адресом Production
   (домен проекта или свой домен): webhook Telegram регистрируется на `PUBLIC_URL` + `/api/auth/telegram/webhook`,
   от него же строятся ссылки в уведомлениях бота. Переменные применяются только к новым деплоям — после смены
   `PUBLIC_URL` нужен Redeploy.
7. Админ назначается с компьютера, напрямую в базе Neon:
   ```
   DATABASE_URL='postgres://...' node services/auth/tools/make-admin.js @ваш_ник
   ```
   (PowerShell: `$env:DATABASE_URL='postgres://...'; node services/auth/tools/make-admin.js @ваш_ник`).

Ограничения:
- Telegram-бот на Vercel получает сообщения через webhook. Пока он там, локальный сайт и VPS с **тем же** ботом
  не запускать: long-polling и webhook мешают друг другу. Для локальной проверки — отдельный бот.
- Запрос и ответ — не больше 4,5 МБ: фото альбома сжимаются в браузере, файлы больше (два видео/аудио каталога) не отдаются.
  Медиа, шрифты и превью кешируются CDN Vercel до следующего деплоя; видео и музыка (запросы по частям) — нет,
  каждый раз идут через контейнер.
- Счётчики `/api/guests/stats` и `/api/album/stats` открыты наружу через `rewrites`, поэтому требуют сессию владельца:
  отдаются только вошедшему пользователю и только по его приглашениям.
- Образ catalog большой (шаблоны ~384 МБ) — если сборка упрётся в лимит размера, шаблоны придётся вынести в Blob.
- Данные (база, фото гостей) хранятся вне Казахстана (Франкфурт) — это временно: по закону РК персональные данные
  граждан должны храниться в РК, постоянный вариант — VPS в Казахстане (выше).

### Цены и контакты

Цена шаблона — у каталога: `PRICE` (по умолчанию 3500 ₸), отдельные цены — `services/catalog/content/prices.json`.
Номер WhatsApp для индивидуального дизайна — `CONTACT_WHATSAPP` в `services.json` (раздел `site`) или в окружении web.

### Базы данных

Сейчас — SQLite, встроенный в Node (`node:sqlite`), по файлу на сервис. Схема меняется
миграциями (`PRAGMA user_version`) при старте. Для публикации каждую базу можно перевести
на PostgreSQL независимо от других: доступ к базе у каждого сервиса собран в его `lib/db.js`.

## Шаблоны

Инструменты — в `services/catalog/tools` (сайту не нужны):

```
node tools/update.js                 скачать/обновить шаблоны и медиа
node tools/update.js --only=296,310  только эти
node tools/clean.js                  убрать чужую рекламу и контакты из шаблонов
node tools/previews.js               снимки превью (нужен puppeteer: cd tools && npm install)
node tools/fetch-content.js          скачать готовый архив шаблонов и медиа (ссылка — CONTENT_URL в .env)
```

После `update.js` и `clean.js` запущенный каталог перечитывает шаблоны сам.

## Проверка

```
node tests/smoke.js
```
Сквозной тест через шлюз: вход, черновик, модерация, ответы гостей, альбом, удаление.
Запускайте **только на тестовом экземпляре** с пустыми базами — тест сам назначает админа:

```
AUTH__DEV_LOGIN_CODES=1 AUTH__DB_FILE=/tmp/t/auth.db INVITATIONS__DB_FILE=/tmp/t/inv.db GUESTS__DB_FILE=/tmp/t/g.db ALBUM__DATA_DIR=/tmp/t/album node run.js --offset=300
BASE=http://127.0.0.1:8324 AUTH_DB=/tmp/t/auth.db node tests/smoke.js
```
